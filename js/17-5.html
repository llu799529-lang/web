JavaScript 的两种定时器

setTimeout 是「过一会儿做一次」，setInterval 是「每隔一会儿做一次」。 两个都返回一个数字 id，拿这个 id 就能用 clearTimeout / clearInterval 把它取消。 下面的演示都是真的在跑，可以随时取消或暂停。

GitHub 仓库

只执行一次setTimeout

3 秒之后做一件事，做完就结束。中途可以取消，取消后什么都不会发生。

3.0s
还没开始
// 3 秒后执行一次
let t = setTimeout(function () {
  console.log('时间到');
}, 3000);

// 反悔了就取消，回调不会再跑
clearTimeout(t);

每隔一段执行setInterval

每隔 100 毫秒跑一次，直到你叫停。下面的秒表就是它一秒跑十次攒出来的。

00:00.0
已执行 0 次
// 每 100 毫秒跑一次，不会自己停
let timer = setInterval(function () {
  ms += 100;
  render(ms);
}, 100);

// 必须自己清，否则一直跑
clearInterval(timer);

时间含义等多久之后执行每隔多久执行一次

典型用途延迟提示、输入防抖、广告 3 秒后关闭秒表、轮播图、时钟、进度刷新
忘了清除会怎样影响不大，跑完就结束一直占着资源，页面越用越卡
两个容易踩的点：
1. 定时器的时间是「至少等这么久」，不是精确时间。主线程忙着执行别的代码时，回调会排队等着，实测常常晚几毫秒到几十毫秒。
2. setTimeout(fn, 0) 不是立刻执行，而是「等当前代码跑完、排到队列末尾再执行」，这正好说明了 JS 是单线程 + 事件循环。
